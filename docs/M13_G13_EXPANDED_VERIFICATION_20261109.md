## Specific failure history and correction

The initial 170,000-shipment report returned HTTP 503 at the 15-second SQL statement deadline ([42536997707](https://github.com/ekamal22/HarborOps-Enterprise-Maritime-Logistics-IT-Operations-Platform/actions/runs/42536997707) and [42537633553](https://github.com/ekamal22/HarborOps-Enterprise-Maritime-Logistics-IT-Operations-Platform/actions/runs/42537633553)). A subsequent version exceeded the 25-second request budget ([42538375530](https://github.com/ekamal22/HarborOps-Enterprise-Maritime-Logistics-IT-Operations-Platform/actions/runs/42538375530)). The report's member INSERT/SELECT RLS path was changed to evaluate signed report authority once per statement, with tenant/report equality still applied to individual rows. The corrected scale run passed. Restricted-role, cross-tenant and policy-mutation checks must continue to be run whenever this security-sensitive path changes.

On the combined branch, M15's original 16-migration assertions were wrong after adding the M13 reporting migration as migration 17. Corrected test expectations cannot, on their own, establish a PASS. The notification action busy-lock issue was fixed on the separate integration branch; the later notification test ambiguity was a Playwright selector matching both the filter option and the visible receipt state. The combined M13 custom-window failure must not be dismissed: on the failed run, the UI did not show the expected 1 November 2026 report period. Its test now asserts the exact filtered API response and preserves any future failure for diagnosis.
