## 2. Required deterministic fixture families

1. **Policy reference:** Tenant A S01-S12 and tenant B decoys from M13_D005_KPI_DECISION_PROPOSAL.md. Seed an anchor UTC T with stable, non-boundary-adjacent values, W=[T-7 days,T), documented immutable IDs, first transition rows, plan values, status/archive state, M6 voyage intervals, M10 input/correction versions and M11 rule states. Verify the complete per-metric expected member set, not just totals.
2. **Temporal boundaries:** UTC midnight/week boundary/leap-year, exact fromUtc/beforeUtc, 60-minute M11 grace and one microsecond over, on-time strict equality, null plan, missing Arrived transition, amendment eligibility, zero denominator and all null variants.
3. **Authorization:** Two organizations, same-looking shipment reference codes, Analyst, Manager, Support, Administrator, Auditor without/with an explicit scoped grant, disabled user, suspended org/membership, second session of same user, foreign organization, and a revocation race.
4. **M11/M10:** Four distinct rules, Open/Acknowledged/Resolved occurrence lifecycle, resolved-but-factually-Active RecordedArrivalLate, recurrence, multiple rule rows per shipment, absent/stale/fresh projection, corrected inputs and parked ARRI/DEPA that never become processed.
5. **Scale:** Empty and small tenant, many smaller tenants, one tenant with at least 170,000 shipments, history/exception fanout, skewed status and archive distribution, wide date windows and expensive but valid filters.
6. **Faults:** SQL role grant denial, short-lived report token tamper/expiry, slow SQL, long report materialization, conflicting concurrent updates, cancelled API request, PostgreSQL restart, report storage failure and retained report cleanup.

The fixture must be seeded into disposable, isolated PostgreSQL only. No production or retained primary volume may be modified.

## 3. Execution tiers and resource isolation

**Tier 0, before implementation:** D-005 approved; reconcile source-backed fixtures, exact DTO/grant mechanism, measured report limits and M13/M15 migration allocation. Do not turn S01 PASS from policy approval alone.

**Tier 1, fast source checks:** After implementation authorization, use manually dispatched GitHub Actions for Release build warnings as errors, unit and contract tests, TypeScript build, documentation link validation, API schema checks, static permission diff and targeted pure-rule tests. Stop on source failure. No local execution.

**Tier 2, real database and HTTP:** In isolated GitHub Actions runners, execute disposable fresh/populated accepted-15 migration upgrades, restricted login/RLS, reference fixture row-by-row reconciliation, typed grant/revocation races, report snapshot pagination, concurrent M11 source changes, outage and cancellation. If a restricted-role suite provisions shared PostgreSQL login names, use an exclusive disposable PostgreSQL **server**, not merely a separate database. Never set an isolation override without verifying exclusivity.

**Tier 3, frozen candidate:** Capture one implementation SHA and changed-file hashes. Run the complete applicable regression, network/proxy bounds, performance plans, multiple-instance admission test, three browser engines and effective mutation campaign. Non-conflicting jobs can be parallelized only with separate runner state, isolated ports, exclusive database instances, browser profiles and artifact namespaces. Avoid repeated full suites on unchanged source.

**Tier 4, independent review:** Freeze evidence, audit manifest/hashes and 25 dispositions, retain failed attempts with fixes attributed to correct source SHAs, request separate S25 review and subsequent G13 decision. Neither S25 nor G13 can be self-certified merely from passing scripts.

**Execution boundary:** Use GitHub Actions exclusively for M13 source-locked verification after completed implementation. Isolate disposable PostgreSQL, browser and build environments, retain redacted evidence, and do not use local tests. Workflows do not authorize production migration, merge or deployment. The E:-drive restriction remains for any separately authorized Windows-local activity.
